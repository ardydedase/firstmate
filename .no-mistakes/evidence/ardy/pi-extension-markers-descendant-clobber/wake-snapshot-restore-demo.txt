# Bug 2 evidence: a lost branch-eligible-rows snapshot no longer wedges wake drain/ack

End-to-end reproduction of the 2026-09-17 episode with the real
`bin/fm-wake-grant.sh` and `bin/fm-wake-drain.sh`, in one live session so the
grant owner stays alive (the owner identity line is abridged here):

```
$ append_wake signal task-a.status  "signal: task-a"
$ append_wake stale  fm-window      "stale: fm-window"
$ append_wake check  some-poll.check "check: some-poll.check.sh: merged"   # main-owned
$ fm-wake-grant.sh activate $$ demo
$ fm-wake-grant.sh publish demo 1 2
```

Reading the transcript:

- The owner record is the new v2 shape; its fifth line `1,2` is the durable
  reserved-sequence list written by publish.
- The rows snapshot is deleted before the branch drain (the 2026-09-17 loss);
  the drain rebuilds it from the live owner record, presents exactly the two
  granted rows, and fences out the main-owned check row.
- The snapshot is deleted again before the acknowledgement; the ack rebuilds
  it too and succeeds, leaving only the main-owned check row queued.
- No `.tmp.*` files leak into state, and main subsequently drains and
  acknowledges its own row, emptying the queue.
